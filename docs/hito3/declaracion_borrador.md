# Declaración del Hito 3 · borrador para revisión de ambos integrantes

**LealCafé · Anchundia Anchundia Luis Antonio y Fuentes Cedeño José Miguel.** Esta propuesta está separada de las evidencias obligatorias del Taller 13. El kit previo solicita una declaración de media página; todavía debe revisarse y acordarse en pareja.

Proponemos desarrollar el cliente como aplicación web adaptable a computadora y teléfono. El acceso desde un navegador evita instalar una aplicación y facilita probar los flujos de cliente y administrador con el mismo backend Go/Gin y PostgreSQL. La página HTML del Taller 13 es una demostración funcional de login y notificaciones; no constituye todavía el cliente completo del Hito 3. La API REST conserva autenticación Bearer y WebSocket entrega los cambios del canje al propietario y los nuevos canjes a administradores. SSE sería suficiente para estos avisos unidireccionales, pero se usa WebSocket para cumplir el contrato solicitado en el hito.

Para el futuro microservicio de pagos proponemos mensajes JSON versionados con `version`, `event_id`, `tipo`, `pago_id`, `compra_id`, `cliente_id`, `monto_centavos`, `moneda` y `ocurrido_en` (fecha RFC3339 en UTC). Tipos previstos: `pago_solicitado`, `pago_aprobado` y `pago_rechazado`; para un rechazo, `motivo_codigo` sin datos bancarios. `monto_centavos` será entero positivo y `moneda` será USD. Un `event_id` único permitirá deduplicar, y el consumidor deberá comprobar el estado persistido antes de acreditar puntos para evitar acreditaciones dobles. No se incluirán tokens ni información de tarjetas. Transporte, autenticación entre servicios, reintentos y reglas de conciliación quedan por acordar al conocer el contrato oficial del microservicio. Esta estructura es una propuesta de diseño, no funcionalidad ya implementada ni requisito textual adicional del Taller 13.
