LealCaf · API de fidelización (2.0.0)

Download OpenAPI specification:

URL: https://github.com/uleam-web-2026-2/web2A-fuentes-anchundia License: Uso académico del proyecto LealCaf

Hito 2: clientes acumulan puntos por compras y solicitan recompensas; administradores registran compras y gestionan canjes. Seis entidades de negocio y Cuenta para autenticación. Los puntos se comparten entre sucursales de la misma cafetería. Las operaciones con summary terminado en (plan) todavía no existen en el servidor. La ejecución actual utiliza PostgreSQL y conserva la base fidelizacion_db existente. Los IDs de los ejemplos son ilustrativos; Bruno obtiene los IDs reales del cliente y de los canjes al preparar.

Autenticación

Inicio de sesión de las cuentas de prueba.

Iniciar sesión

Pública. Verifica usuario y contraseña de la cuenta; devuelve un JWT de una hora. No existe registro ni CRUD de cuentas. La cuenta cliente demo está asociada a un cliente dedicado cuyo ID puede ser distinto de 1.

required

Confirmar o cancelar un canje

Solo administrador. Desde solicitado permite confirmado (revalida saldo y descuenta puntos) o cancelado (no descuenta). Confirmado y cancelado son finales. Una transición desde un estado final o hacia solicitado devuelve 422; destino desconocido, 400.

Authorizations:
bearerAuth
path Parameters
id
required
integer >= 1
Example: 1

Identificador entero positivo del recurso.

Request Body schema: application/json
required
estado
required
string
Enum: "solicitado" "confirmado" "cancelado"

confirmado o cancelado son destinos válidos desde solicitado. solicitado es un valor conocido, pero no es destino permitido y devuelve 422. Un valor desconocido devuelve 400.

Responses

Servidor local; localhost:8080 apunta a la misma interfaz.
